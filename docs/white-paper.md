# 意图式契约语言的边界

## Lemma 纸面原型的复盘与转向

> 版本：v0.3 草案
>
> 日期：2026-10-17
>
> 状态：早期草稿。本版由对话产生的 v0.2-rc1 修订而来，修订要点是收敛结论、标注估算、补充相关工作。所有数字除非另行说明，均为未经验证的估计。

## 摘要

AI 辅助编程（vibe coding）的核心痛点之一，是代码、文档、测试、断言四份产物互相漂移，缺乏单一真相源。Lemma 曾试图在语法层面强制每个函数携带 `pre` / `post` / `examples` 意图块，让同一份意图同时充当规格、测试、文档与运行时断言。

本文记录了一次纸面原型实验：在纯逻辑、带 IO、带并发三个任务上，检验「意图能否被声明式契约无损承载」。实验结果不支持「声明式契约彻底失效」的强结论，而支持一个更窄、也更可操作的结论：仅约束输入输出的点状契约，在副作用、时序与并发场景下表达成本急剧上升，且 spec 本身会空洞、自相矛盾。

据此，项目从「验证意图」转向两个方向：为 AI 生成的契约做静态体检（linter），以及在窄领域内用受约束构造替代事后验证。

## 1. 问题背景

vibe coding 把人的角色从「编写者」变成「意图提供者与审阅者」。这个转变暴露了一个结构性缺口：AI 生成代码的典型失败模式（幻觉 API、边界错误、与意图漂移）无法在生成过程中被有效拦截。

现有语言的反馈通道——类型系统、测试、运行时断言、文档——全部发生在代码生成之后，且彼此独立维护。一份意图被重复表达四次，就会产生四份漂移。Lemma 回应的是一个诱人的直觉：如果意图只被表达一次，且这份表达同时是规格、测试、文档与断言，漂移是否就从物理上被消灭了？

## 2. Lemma 的核心假设

Lemma 的设计可以压缩为一条假设：

> 每个函数的意图，都可以被一个由 `pre` / `post` / `examples` 构成的声明式契约无损承载；编译器在构造期验证这份契约。

其中 `pre` 是前置条件，`post` 是后置条件，`examples` 是输入输出样例。三者共同构成「单一真相源」。

这条假设隐含三个可被证伪的子假设：

- 赌注 A：真实业务函数的意图能写成 `post` 表达式。
- 赌注 B：`examples` 能覆盖副作用与失败路径。
- 赌注 C：带 IO / 并发的函数不会被降级到「运行时检查」。

## 3. 方法：纸面原型与预注册

在写编译器之前，我们用纸面原型检验上述假设。角色分离为「Spec 作者」与「审阅者」；作者只看桩文件，先写 spec，后写 body，中途不得回改。

三个任务分别覆盖三个正交维度：

| 任务 | 维度 | 业务规则数 |
|---|---|---|
| 任务 1 折扣计算 | 纯逻辑 | 5 |
| 任务 2 用户注册 | 带 IO | 5 |
| 任务 3 批量拉取 | 并发 + 重试 | 4 |

**方法缺陷（如实记录）：** 任务 1 执行时未引入预注册；N=1；Spec 作者与审阅者由同一人扮演；所有数字均为估算。因此本文结论是「观察与假设」，不是「证伪证明」。

## 4. 观察

### 4.1 任务 1：折扣计算

桩文件要求会员折扣、券叠加、去重、触底、黑名单拒绝。Spec 作者最终把 `post` 退化为粗粒度边界校验（`final >= 1 && final <= price`）。

**但这里必须做一次归因修正。** `compute_discount(price, tier, coupons)` 是纯函数，结果完全由输入决定，不存在「路径约束」问题。spec 写不精确有三个更直接的原因：

1. 桩文件本身缺参数：规则要求判断 `category == "any"`，但 `category` 未作为参数传入。
2. 桩文件类型不一致：要求用 `tier == Blacklist`，但 `Blacklist` 不在 `Tier` 枚举里。
3. 作者在时间盒内没能写出完整的算术公式。

换言之，这个任务说明的是「题目质量与写 spec 的难度」，而不是「点状契约的数学极限」。

### 4.2 任务 2：用户注册

涉及邮箱格式、密码强度、入库原子性、邮件异步重试。作者发明了语言里不存在的 `predicate ... ! IO`，核心副作用约束在 `post` 里完全消失。

这暴露了两个真问题：纯表达式契约缺少表达外部状态与时序的词汇；以及「写 spec 的人会本能地发明语言没有的语法」。但它不是「声明式契约必然失效」的证据——问题在于 Lemma 主动把 spec 表达式限制为纯函数，而非声明式方法本身不能表达状态（见第 6 节）。

### 4.3 任务 3：批量拉取

涉及并发上限、重试、指数退避、部分失败可定位。作者放弃对外部状态的表达，退化为纯结构守恒断言，并写出了一条与 `examples` 直接矛盾的 `post`。

这条自相矛盾是三个任务里最有价值的观察：**spec 本身也需要被验证。** AI 生成的契约同样可能空洞、不可达、自相矛盾，而人类审阅者未必能发现。这直接导向第 8 节的 linter 方向。

## 5. 归因：失败来自哪里

把三个任务的现象归因，可以得到一张比「结构性失效」更准确的表：

| 现象 | 更可能的归因 | 是否语言的结构性极限 |
|---|---|---|
| 任务 1 写不出精确 post | 桩文件缺陷 + 作者能力/时间 | 否 |
| 任务 2 发明 `predicate` | spec 语言未定义 + 缺状态词汇 | 部分 |
| 任务 3 spec 自相矛盾 | 作者错误，未被检查 | 否（恰恰是工具缺口） |

结论：实验没有证伪「声明式契约」，它证伪的是「不提供状态/时序词汇、又没有 spec 体检工具的极简契约语言」。

## 6. 点状约束与轨迹约束

把「点状 vs 路径」的对立换成更准确的表述：**值约束 vs 轨迹约束**。

值约束只依赖输入与输出：`P(x, f(x))`。轨迹约束依赖状态转移序列与副作用时序。二者是不同的对象，前者无法表达后者，这是定义使然，不是新的数学发现。

关键点在于：轨迹约束并非不可表达。Eiffel 用 `old`，Dafny 用 `old` / `modifies` / ghost 变量，TLA+ 直接描述状态序列，Verus 写历史不变量。这些语言的共同经验是：表达做得到，但**成本与专业门槛高**。因此真正的问题不是「能不能」，而是「在 vibe coding 场景下，这个成本是否划算」。本文目前的证据只支持：在极简纯表达式契约下，成本高于收益；对「带状态词汇的契约语言」是否划算，尚未检验。

## 7. 相关工作

同一堵墙的几次撞击，结论各不相同：

- **Design by Contract（Eiffel）：** 契约能写，但工业界使用率低，成本与收益不成比例。
- **Dafny / Verus / F\*：** 证明状态与时序约束可行，但需要专职验证专家，不面向 vibe coding。
- **TLA+：** 描述分布式时序规格成熟，但离代码远，是设计期工具而非构造期工具。
- **精化类型（Liquid Haskell 等）：** 在类型里表达部分语义成功，但明确放弃了副作用时序。
- **LLM structured output / JSON Schema：** 约束输出格式有效，约束输出语义无效。

共同教训：约束「结构、格式、静态边界」的声明式方法成功了；约束「业务语义、状态演化」的声明式方法要么成本高，要么被主动放弃。Lemma 的错误不是选错了目标，而是低估了表达业务语义所需词汇的代价。

## 8. 结论与后续

三个观察转化为两个可落地的方向：

1. **契约 linter（优先）。** 对 AI 或人类生成的契约做静态体检：空洞检测、分支可达性、`examples ⊨ post` 一致性、规则覆盖率。这是任务 3 的直接产物，不依赖任何未验证的语言设计，可以立刻实现并产生价值。
2. **窄领域受约束构造。** 在不变式清晰的领域（转账、状态机、协议）里，用「合法算子集 + 类型配平」替代事后验证。该方向的适用边界本身仍是开放问题。

语言本身的路线（继续做一门带状态词汇的契约语言）暂不推进，除非第 1 项证明「spec 体检」存在稳定需求，且能回答第 6 节遗留的成本问题。

## 9. 局限与可证伪性

- 本文的实验是纸面原型：N=1、作者与审阅者同源、任务 1 缺预注册。
- 所有覆盖率和行数均为估计，未做双盲严格测量。
- 三个任务不构成对一类方法的统计证伪，只构成对「极简纯表达式契约」的成本观察。

什么会让本文的结论改变：

- 一份带状态/时序词汇的契约语言，在同等作者和时间盒下，把三个任务的 spec 覆盖率显著提高且成本可接受；
- 对 10 个以上真实任务的对照实验（spec vs 纯测试），显示 spec 在缺陷拦截率上稳定优于测试。
