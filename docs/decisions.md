## 对话自己的最终结论

1. 最初目标「创建一门新语言」最终被放弃：对话认定 Lemma 的核心假设已被纸面实验证伪。
2. 项目转向：不发布语言，改为发布一份「负面实证白皮书」——记录「声明式契约无法无损承载业务意图」的失败过程。
3. 立场选定为 C（领域问题重述），标题定为《意图式契约语言的边界与失效机制》。
4. 下一步（对话版本）的路线：建公开 GitHub 仓库、归档三份实验记录、补 `execution_date`、发布 v0.2 final。

## 关键决策时间线

- 语言名演变：Tessera（被否，因「四不像拼接」）→ Witness → Vera → **Lemma**。
- Lemma 定义：每个 `fn` 强制携带 `pre` / `post` / `examples`，作为「单一真相源」；验证三级降级为 `verified` / `runtime-checked` / `error`。
- 8 条设计决策（decisions-v0.1.md）：含 #6「examples 能否调用其他函数」、#7「spec 能否引用局部辅助函数」等，对话认为这些必须在写 EBNF 与形式语义前锁死。
- 三个赌注：A（真实业务函数能写出 post）、B（examples 能覆盖副作用/失败路径）、C（IO/并发函数不会被降级）。
- Paper Prototype 三任务：折扣计算（纯逻辑）、用户注册（带 IO）、批量拉取（并发+重试）。
- 对话判定的覆盖率：任务 1 为 1/5 = 20%，任务 2 为 2/5 = 40%，任务 3 为 0/4 = 0%；对照组 pytest 覆盖率均为估算（约 90%）。
- 最终动作：组装 v0.2-rc1 全文；P0（覆盖率算法、可复现附录、形式化骨架）、P1、P2 补丁；附录 A 证据仓库待建。

## 争议点（与评审的冲突）

- 对话把「命题 1」当作不可能性定理，评审认为它是定义层面的同义反复，不构成对一类方法的证伪。
- 对话把任务 1 归为「路径约束」，评审认为它是纯函数、且桩文件本身缺参数（`category`、`Blacklist`）。
- 对话把 20%/40%/0% 与 90% 当作实证对比，评审认为全部是估算，且 N=1、作者与审阅者同源。
- 对话把任务 2/3 的作者错误（非法 `predicate`、spec 自相矛盾）归为语言结构性失败，评审认为这恰恰指向「spec 体检工具」这一机会。
